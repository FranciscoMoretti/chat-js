## Fixed deployment defect

The app-to-EVE request initially received HTTP 401 from Deployment Protection. ChatJS depended on a separately provisioned automation bypass secret. It now reads the current invocation's identity using `getVercelOidcTokenSync()` and sends `x-vercel-trusted-oidc-idp-token` only to its own deployment origin. Separate workers receive no project identity, redirects remain disallowed, and local execution does not require Vercel identity. The obsolete bypass-secret configuration was removed.

The fix passed the deployed native execution checks, `bun lint`, all 11 workspace type checks, 1,231 app unit tests, and 394 CLI tests. Focused tests cover identity refresh between requests, separate-worker isolation, local execution, and guest admission.

## Findings to carry into review

1. **Unknown creation recovery blocks the account.** The initial rejected dispatch left an application operation without a native binding. Replaying it remained fenced, and a new conversation for that account was rejected with `creation_recovery_unavailable`. A fresh test account was used to verify the corrected deployment. This is ChatJS's recovery policy, not a native connection requirement. Do not interpret the successful later run as recovery of the original operation.
2. **Managed deletion is unnecessarily coupled to the PostgreSQL coordinator.** Native EVE can end the managed session and clean its sandbox. The app currently demands its additional PostgreSQL retirement, queue-fencing, and erasure contract before allowing deletion. A follow-up should separate app-resource cleanup from EVE's native session lifecycle and retention, with explicit guarantees for each.
3. **Native retention has defined limits.** The pinned EVE docs derive run retention from the trace policy; private and unknown-audience sessions outside development request zero retention by default. Supporting Worlds delete payloads at termination, while metadata and externally exported data can remain. The successful probe establishes native termination, sandbox removal, and unavailable session history; it is not proof of erasure from every provider or telemetry destination. See [Workflow retention](https://vercel.com/docs/workflows/retention) and the installed EVE `docs/agent-config.md` section “Run data retention.”
