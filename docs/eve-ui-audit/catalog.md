# EVE UI parity: file-by-file catalog

Baseline: `origin/main` **4584f093835f1667c010c8fc20c502fa3f2bde41**. EVE: **da78b23ae977ecafb997d36eb12b3c861b8057e1**. Audited 2026-09-20.

Scope: chat headers; project pages and CRUD dialogs; sidebar/history/search; document headers, actions, previews, editing, version selection; their route/cache/provider boundaries. Each row names one real file, including unchanged primitives and deleted main counterparts. This is exhaustive for the explicitly cataloged surface, **not a claim that every application feature has parity**. Boundary-only rows explicitly identify areas not deeply audited.

Evidence: source comparison for every row; browser observations and six local screenshots for project creation and empty project layout. Document/header behavioral findings are source-confirmed unless marked otherwise. No product code changed. The previously accepted logical controller and optimistic first send are not reopened.

Status: **=** identical blob, **M** modified, **A** EVE-only, **D** main-only. “Improvement/adaptation” does not mean bug; “gap” identifies a missing or changed main contract. H/P/S/D/O IDs resolve in [findings.md](findings.md). Source links are pinned to the exact revisions.

Catalog: **100 files**. Machine-readable companion: [catalog.json](catalog.json).
