# @chat-js/sandboxes

## 0.2.0

### Minor Changes

- [#865](https://github.com/FranciscoMoretti/chat-js/pull/865) [`d0a4016`](https://github.com/FranciscoMoretti/chat-js/commit/d0a4016e473c532aa7d02226a9e7c6d893ad5882) Thanks [@FranciscoMoretti](https://github.com/FranciscoMoretti)! - Add an optional persistent filesystem capability to the shared sandbox provider contract and its Vercel registry implementation. Use app-owned EVE resource lifecycle handling when the installed provider supports persistent files. No-provider and execution-only installations explicitly disable EVE filesystem access without resolving sandbox credentials. Cleanup resolves providers only for outstanding owned resources. Requires a fresh world and current database schema. Release the shared package before distributing consumers of its new persistent export.

- [#853](https://github.com/FranciscoMoretti/chat-js/pull/853) [`393fd57`](https://github.com/FranciscoMoretti/chat-js/commit/393fd573f47819f39801a9edf4166b1ed804f4b3) Thanks [@FranciscoMoretti](https://github.com/FranciscoMoretti)! - Separate optional sandbox infrastructure from code-execution tools. Add a shared provider and lifecycle contract with Vercel and Daytona implementations, selected through `--sandbox-provider`. Install the generic `code-execution` tool instead of the former `vercel-code-execution` or `daytona-code-execution` items. Saved-code execution reuses the generic executor and requires an explicit sandbox selection when none is installed.

  This release targets newly scaffolded apps. Upgrading apps generated by previous releases is unsupported; no compatibility aliases or migration shims are included.
