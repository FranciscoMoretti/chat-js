# P0/P1 implementation: independent conversation views

Scope: the approved P0/P1 slice of [the migration plan](../plans/m04-composable-ui-plan.md), against main `18db694b`. P2–P9 are not implemented. No Eve migration, UI component factory, CLI-template migration, merge, or deployment.

## Implemented boundary

- `ConversationView` is an ordinary provider under the existing runtime binding. Named view controllers retain their own cursor and followed run across route unmounts; the runtime retains the canonical tree and execution. Shared runtime snapshots are referenced rather than copied into another mutable message store. Disconnecting a view releases its subscription and invalidates pending selection work without stopping execution.
- Existing message lists, message actions, retry, parallel cards, navigation, suggested actions and composers use view selectors/commands. Explicit message IDs remain message scope; they do not resolve through a global selected transcript. `Thread.regenerateRun` returns the exact run and defaults to no canonical following; existing `regenerate` behavior is preserved.
- Existing `ChatInputProvider` keeps draft/model/tool/attachment state independent. Draft storage is namespaced by caller, stable conversation/provisional scope and view. Restoration precedes editor mounting. Upload preparation and completion check mount, selection and consumed-draft generations. Pending batches are tracked separately so an old completion cannot clear a newer batch's loading state.
- The existing resizable layout and document panel live at workspace scope. Opening a document captures the source runtime, view, message, model and read-only state. Toolbar commands retain that origin after navigation/unmount. A workspace subscription continues document stream updates after the source view disappears. Inline previews use streaming content only when their origin matches. Changing the panel target remounts its local editor/version/save state.
- No P2 split into public ComposerInput/ComposerSubmit/ModelPicker modules is included. The existing components remain the reference UI. Exact document revision/persistence semantics remain P4 work; this slice fixes origin routing and lifetime.

## Linear runtime integration handoff

Reviewed M07 at commit `688c7e944cb66397ec2a0e2a80f1557dc7325b07`, including
`examples/minimal-next/lib/projection.ts`, `lib/send-turn.ts`, `app/chat.tsx`
and its findings. That example exercises published Eve 0.52.1. Its evidence is
separate from this PR, which continues to use the existing Thread runtime.
Neither the private tree prototype nor this UI change establishes a supported
production Eve runtime.

| Boundary | P1 proves | Later public-runtime integration must preserve or verify |
| --- | --- | --- |
| Projection | Two views select independently from one canonical Thread snapshot. | Use Eve's project-local typed projection (`useEveAgent<ProjectData>` and `projectReducer`), validate tool output, and remount the session binding when its identity changes. Do not cast Eve messages into the current Thread/AI SDK message shape. |
| View lifetime | Unmount releases view subscriptions without cancelling execution; draft and selection scope remain independent. | Verify attachment, replay and reconnect against durable runtime state. P1's in-memory remount test does not prove process-restart recovery. |
| Pending input | No new approval runtime is implemented. | Preserve authoritative `input.requested`/`input.resolved` projection and request IDs. Do not invent turn IDs for the empty approval-continuation turn ID observed by M07. |
| Cancellation | Stop targets the exact existing Thread run. | M07 cancellation is cooperative, not prompt provider abortion. Its response can settle before the durable cancellation event. After accepted cancellation, the next send/respond performs public catch-up after the command; ordinary sends avoid that extra replay. Verify a newly appended response after Stop, not merely an accepted command or an older matching message. |
| Workspace actions | Commands retain their originating runtime/message after view navigation or unmount. | Verify how a linear runtime expresses that origin before enabling those commands. Existing Thread ancestry is not evidence of public Eve historical branching support. |
| Creation and ownership | No new creation or ownership service is implemented. | Retain M07's owner-scoped binding and fail-closed reservation for ambiguous creation. Distributed create-once, transparent crash-time creation recovery and historical branching remain separately tracked upstream work. |

Linear integration can advance with those explicit limits. CLI materialization
must validate its selected public runtime and source graph independently; this
PR adds no installer recipe or universal compatibility guarantee. P2 component
extraction and later runtime integration remain outside the approved P0/P1
implementation boundary. UI state guards do not resolve upstream execution gaps.

## Verification

- `apps/chat/lib/chat/view-store.test.ts`: six regression tests with the real current Thread engine and controlled transport. Covers separate sends/paths, pending user visibility, selection away/back, unmount without cancellation, targeted Stop, regeneration, workspace command origin, and remount generation invalidation.
- Final `bun lint` (4 tasks), `bun test:types` (3 tasks), and the mounted fixture TypeScript check passed.
- App unit suite: 155 tests across 33 files passed. Thread suite: 65 tests, 198 assertions passed.
- All 12 PR checks passed at implementation commit `212fa83c`, including Playwright, CLI Scaffold and the Required gate. This does not establish the separate M07 runtime integration contract.
- [Mounted proof](m04-p1-mounted/README.md): copies a test-only host into a temporary Next route, mounts the actual MessagesPane/MultimodalInput/ChatInputProvider twice against one ApplicationThread, and removes the route in `finally`. Uses authenticated development layout and actual Query providers, controlled model transport and intercepted upload responses. Covers path/draft/model/edit isolation, home draft reload, stale uploads, independent pending upload batches, workspace toolbar ancestry after navigation, retained draft/selection after remount, and zero page errors. This is not a live model or blob-service success claim.
- Live reference app: Next 16.3.0/Turbopack started through `bun dev`; authenticated through `/api/dev-login`; real composer input and submission rendered. Next MCP reported no compilation or runtime errors. The actual `/api/chat` model call failed with `GatewayAuthenticationError`; the shared development credentials also returned Unauthorized for the model catalog. Credential refresh was requested without exposing secrets. Live successful model completion remains unverified.

## Review and corrections

Independent spec and standards reviews found and drove fixes for unstable provisional draft storage, stale attachment insertion, stale upload cleanup clearing a newer batch, and inline document previews reading another origin's streaming content. Removed the now-unused artifact stream callback API. Browser testing additionally exposed the initial empty editor callback racing draft restoration, which is fixed by restoration before editor mount.

The PR remains a draft. The broader migration is not complete, and the credential-dependent live-model gate must not be reported as passing.
