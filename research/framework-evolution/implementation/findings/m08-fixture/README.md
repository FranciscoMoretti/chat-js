# M08 installation/composition spike

Run with Bun 1.3.11:

```sh
bun install --frozen-lockfile
bun run proof
```

The fixture pins standalone shadcn 4.21.0 locally and invokes its installed CLI with Bun. It serves universal registry items on an ephemeral loopback port and creates two temporary projects. `minimal` installs core + one provider; `expanded` additionally installs an ordinary bundle whose direct-URL registry dependencies are a paired tool and a CSV editor. The alternative provider is never selected. This is not a functioning ChatJS/Eve app and expanded is not the full reference demo.

Checks prevent concrete integration mistakes: omitted source must really be absent; exclusive packages must be absent from manifest and Bun lock; inferred outputs and mounted keys must reject invalid TS; a new layout install must preserve edited composition. The small requirement example rejects missing/conflicting service choices and reuses a shared choice. It is proposed ChatJS semantic glue, not a replacement registry resolver.

`proof.ts` is the entire executable spike. It writes stable `evidence.json` and `layout-replacement.diff` here, then deletes only its own temporary projects and stops its server. The local fixture lock pins the installer. Generated targets use pinned direct package versions and fresh Bun locks; no registry lock or transitive package compatibility promise is invented. Their complete inventories are saved in evidence.

`demo.development.resolved.json` and `demo.production.resolved.json` were separately captured from main's real `applyDefaults(chat.config.ts)` on commit `18db694b`. They define the current reference settings and are not generated by the fixture. Reproduce from `apps/chat`:

```sh
bun -e 'import c from "./chat.config.ts"; import {applyDefaults} from "./lib/config-schema.ts"; console.log(JSON.stringify(applyDefaults(c),null,2))'
NODE_ENV=production bun -e 'import c from "./chat.config.ts"; import {applyDefaults} from "./lib/config-schema.ts"; console.log(JSON.stringify(applyDefaults(c),null,2))'
```

Observed: proof passed; both target typechecks passed including negative compile cases. Root `bun lint` and `bun test:types` passed using Turbo's shared cache (4 and 3 tasks respectively). These root scripts do not include this isolated fixture, so its generated-project checks are separate. The existing CLI suite also passed: 34 tests, 320 assertions. No production Next build was run.

Environment notes: the first root frozen install failed in `fs-xattr` because cached node-gyp lacked `nopt`; `bun install --frozen-lockfile --ignore-scripts` installed the workspace for these research checks. The first Bunx shadcn invocation found an incomplete shared cache missing `prompts`; installing shadcn locally in this fixture and invoking that pinned entry resolved it. No other worktree or shared cache was modified to repair these issues. No native-addon runtime validation is claimed.
