## Model variants

When a model is tagged with `reasoning` by the gateway, ChatJS creates two entries in the model selector:

| Variant   | Model ID                 | Behavior                         |
| --------- | ------------------------ | -------------------------------- |
| Reasoning | `openai/gpt-5-reasoning` | Applies ChatJS reasoning options |
| Standard  | `openai/gpt-5`           | Uses agent and provider defaults |

Both variants point to the same underlying API model. The `-reasoning` suffix controls whether ChatJS adds its reasoning options to the request.

### UI

When a model responds with reasoning content, the UI renders a collapsible "Thinking" section above the answer. Expand it to read the reasoning text or summary the provider returned.

While the model is still generating, the reasoning section streams in real time.

## Supported providers

The ChatJS model picker maps a reasoning selection to provider options using the model catalog’s `owned_by` field. For native agent calls, configure reasoning in `agent/agent.ts` using [EVE’s reasoning options](https://eve.dev/docs/agent-config#reasoning-effort).

| Provider | Mechanism | Notes |
| --- | --- | --- |
| OpenAI | `reasoningSummary` provider option | `gpt-5`, `gpt-5-mini`, and `gpt-5-nano` also set `reasoningEffort: "low"` |
| Anthropic | `thinking` provider option | Budget of 4096 tokens |
| Google | `thinkingConfig` provider option | Budget of 10,000 tokens |

## Customization

### Adjusting reasoning budgets

In `integrations/chat/model-options.ts`, change `ANTHROPIC_REASONING_BUDGET_TOKENS` or `GOOGLE_REASONING_BUDGET_TOKENS`. The provider option applies when the user selects that model’s reasoning variant.

### Choose which variants appear

To offer a standard model without its reasoning variant, include the base ID in `webModels.modelIds` in `integrations/chat/models.ts`. Include the suffixed ID as well if you want both. This list defines the full set of models offered in the signed-in picker. See [model visibility](/customization/models#visibility-and-preferences).

Adding the base ID to `ai.disabledModels` hides both variants. For a catalog-wide change to how the picker generates variants, edit `buildWebChatModels` in `lib/ai/web-chat-models.ts`.
