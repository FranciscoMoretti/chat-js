title: Configuration
description: Install capabilities and configure runtime policy in ChatJS
---

ChatJS separates **installed source**, **runtime policy**, and **deployment infrastructure**. The CLI installs tools, features, one gateway, and one storage adapter. `chat.config.ts` supplies branding, model defaults, authentication and guest policies. Environment variables supply credentials and deployment connections.

## Runtime configuration

The generated `chat.config.ts` is parsed by `lib/config-schema.ts` and exported as `config` from `@/lib/config`. Use the installed gateway's discriminator and override only the settings you need. This example applies to a Vercel gateway installation:

```typescript title="chat.config.ts"
import type { ConfigInput } from "@/lib/config-schema";

const config = {
  appName: "Your App Name",
  appPrefix: "your-app",
  organization: {
    name: "Your Company",
    contact: {
      privacyEmail: "privacy@example.com",
      legalEmail: "legal@example.com",
    },
  },
  ai: {
    gateway: "vercel",
    tools: {
      followupSuggestions: { enabled: true, default: "openai/gpt-5-nano" },
      deepResearch: {
        defaultModel: "google/gemini-2.5-flash-lite",
        finalReportModel: "google/gemini-3-flash",
        allowClarification: true,
        maxResearcherIterations: 1,
        maxConcurrentResearchUnits: 2,
        maxSearchQueries: 2,
      },
    },
  },
  features: { parallelResponses: true },
  authentication: { google: false, github: true, vercel: false },
} satisfies ConfigInput;

export default config;
```

Model settings do not install their tools. Follow-up suggestions retain an `enabled` runtime setting. Search, retrieval, code execution, image/video generation and deep research do not have `enabled` configuration fields.

## Install tools and features

Run commands inside your generated app, using the CLI version appropriate to your installation:

```bash
bunx @chat-js/cli@latest add tavily-search deep-research
bunx @chat-js/cli@latest add code-documents saved-code-execution
bunx @chat-js/cli@latest add attachment-uploads --storage-provider vercel-blob
bunx @chat-js/cli@latest add mcp
```

| Installation | Requirements |
| --- | --- |
| `tavily-search` or `firecrawl-search` | Selected provider's credentials. One `webSearch` provider serves chat and research. |
| `deep-research` | Text documents, document reading and a search provider. Missing search defaults to Tavily. |
| `saved-code-execution` | Code documents, document reading and a compatible `codeExecution` provider. Missing execution defaults to Vercel Sandbox. |
| `generate-image` / `generate-video` | Compatible gateway capability, a default media model and persistent storage. Only the built-in Vercel gateway declares video support. |
| `attachment-uploads` | Persistent storage. Configure limits separately under `attachments`. |
| `mcp` | `MCP_ENCRYPTION_KEY`, including installations with no connectors yet. |
| `vercel-analytics`, `vercel-speed-insights`, `langfuse` | Independently installed telemetry. Langfuse requires its keys. |

Planning resolves transitive registry dependencies and validates the resulting selection before installation. Memory storage is appropriate only when no installed feature needs persistent files. An external adapter's metadata is a declaration, not proof of live provider behavior.

## Replace providers

Gateway selection installs `lib/ai/gateway.ts` and its typed defaults. Changing only `ai.gateway` cannot switch providers:

```bash
bunx @chat-js/cli@latest add --gateway openai --replace
bunx @chat-js/cli@latest add firecrawl-search --replace
bunx @chat-js/cli@latest add tavily-search --replace
```

Replacement requires `--replace`. Modified or untracked provider source requires review and explicit `--overwrite`. Keep a version-control checkpoint before replacing customized source. The CLI preserves runtime model overrides, so review their IDs for the selected gateway and run `bun run setup` and `bun run fetch:models` after supplying credentials. Registry addresses can select external providers too. The CLI removes unused dependency entries that its installation receipt owns, and refreshes its marked environment-example sections. It preserves pre-existing dependencies, user-changed versions, dependencies referenced by remaining source and environment entries outside those sections. Older installations without receipts need manual dependency review. Environment entries outside the marked sections, including credentials from older scaffolds, are treated as user-owned and preserved. After replacing a provider in an older app, review those unmarked entries and remove obsolete examples manually; the CLI cannot distinguish old generated entries from your own values.

Search replacement uses the same `webSearch` slot for direct search and research. Saved-code execution requires an executor export, in addition to a `codeExecution` tool. A second independent sandbox provider and its resource cleanup remain release gates. See [Self-hosted deployment](../deployment/self-hosted) for the infrastructure acceptance boundary.

A reproducible minimal scaffold omits document tools as well as optional integrations:

```bash
bunx @chat-js/cli@latest create minimal-chat --yes --no-documents --no-mcp --no-attachments --no-electron
```

## Runtime policy and credentials

Authentication booleans enable GitHub, Google or Vercel OAuth and require the corresponding credentials. `anonymous` configures guest model/tool access, credits and rate limits. Retention additionally needs an operational cleanup schedule and lifecycle support.

`features.parallelResponses` controls parallel responses. `attachments.acceptedTypes`, `maxBytes` and `maxDimension` control installed upload behavior. Neither setting installs its feature. Branding, organization/legal text and pricing display are also runtime configuration.

Read installed descriptors and `.env.example` for credentials, then run `bun run check-env`. Never put secrets in `chat.config.ts` or `--storage-config`. See [Config reference](../reference/config) and [Gateway overview](../gateways/overview).
