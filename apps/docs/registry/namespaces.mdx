---
title: Namespaces
description: "Configure an external registry namespace, address items by name, and see how a registry source relates to an item’s category and installed paths."
---

Configure registry source aliases such as `@chatjs` or `@acme` in `components.json`. An address such as `@chatjs/deep-research` identifies an item from that source. The item's `meta.chatjs.kind` identifies its category independently of its name.

Source folders, public item names, and installed paths are separate. The built-in Vercel item is named `vercel-gateway`, is authored under `packages/registry/src/gateways/vercel/`, and installs into `chatjs/providers/gateway.ts`. Changing a registry alias does not change an item's explicit file targets.

Keep the generated `@chatjs` entry for your app’s registry version and UI base. Merge an external source into the existing `registries` object. This excerpt shows the new entry.

```json
{
  "registries": {
    "@acme": "https://example.com/r/{name}.json"
  }
}
```

Install an external tool with `npx chat-js@beta add @acme/my-tool`. Replace the example registry address with your publisher's endpoint.

A third-party gateway still belongs to the gateway category. Its namespace identifies who distributes it, while its metadata identifies its ChatJS contract. Review explicit file targets when composing items from different registries. A namespace does not automatically isolate installed files or registration keys.
