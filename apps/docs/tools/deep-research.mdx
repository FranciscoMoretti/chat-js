## Overview

Deep Research appears under **Agent → Extensions**, with **Source: ChatJS**. Its execution files use EVE and Zod; they do not require ChatJS authentication, database tables, search adapters, or file storage. ChatJS supplies the progress renderer when installed in a ChatJS app.

```bash
bunx chat-js@alpha add deep-research
```

For an EVE-only installation, use the native item from your deployed registry:

```bash
eve add https://your-registry.example/r/eve/deep-research.json
```

Replace the example URL with your registry endpoint. The registry build emits `dist/r/eve/deep-research.json` and its catalog. Deploy that output or publish a package containing it before using a remote URL. This distribution includes only native agent files and EVE/Zod dependencies. Use the ChatJS command above when you also want its progress renderer.

The bundle installs its workflow under `agent/tools/deepResearch.ts` and supporting files under `agent/lib/research/`. It is a source-file integration, not a separately mounted extension package.

## Capabilities and configuration

Research uses EVE's built-in agent copies. Unlike declared subagents, those copies inherit the parent agent's tools, connections, skills, instructions, model, approvals, and shared sandbox. Install search or retrieval capabilities on the parent through EVE's documented registry commands or native connection files. Research needs no ChatJS provider selector or provider-specific adapter. EVE owns connection discovery, credentials, approvals, and execution.

Configure the model and reasoning in `agent/agent.ts`, connections in `agent/connections/`, and the sandbox through EVE's sandbox configuration. Research uses the same model configuration as the parent; separate research model settings in `chat.config.ts` are no longer used. In a ChatJS app, native copies also inherit the application's model wrapper and optional billing hooks.

Workflow-specific bounds live in `agent/lib/research/configuration.ts`:

```ts
export const researchOptions = {
  allow_clarification: true,
  max_concurrent_research_units: 2,
  max_researcher_iterations: 1,
  search_api_max_queries: 2,
};
```

The supervisor may choose up to `max_concurrent_research_units` topics per decision round; topics are processed sequentially. It makes at most `max_researcher_iterations + 1` decisions. The search-query setting is guidance to the researcher, not a runtime limit on a connection. EVE's own agent limits and approval policies still apply.

## Research and files

The calling agent supplies `request`: the full task, relevant conversation context, scope, and any input sandbox paths. Research does not fetch a ChatJS conversation or assume a web account. If clarification is needed, it returns questions for the calling agent to ask.

The workflow writes a brief, cited source findings, compressed notes, and a final Markdown report under `research/run-<encoded-call-id>/`. Later phases read those files. Native copies share the parent sandbox, so they can use its existing files and installed capabilities.

Each invocation uses its own directory. Whole-file writes can be retried without appending duplicate content. Intermediate files follow EVE's sandbox lifecycle; if they disappear, research fails explicitly instead of silently omitting evidence.

## Delivery and presentation

The final result contains a report title and sandbox path. Research does not upload the report or create a ChatJS document.

- In ChatJS, install `attach-workspace-file` so the calling agent can use `attach_workspace_file` to attach the report as a download. The Research composer selection makes the attachment tool available when its storage is configured. Research itself only needs the EVE sandbox for its files.
- Other channels can use their native file delivery capabilities.
- Without a delivery capability, the agent explains that the report exists in its sandbox rather than inventing a download link.

The optional ChatJS renderer shows phase progress and report readiness. The separate publication result supplies the download card and optional viewer action. Viewers and document editors are not required. Published downloads remain unchanged when later research or sandbox edits create new files.
