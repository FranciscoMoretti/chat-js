title: Tools Overview
description: Install and distribute typed ChatJS tools with shadcn registries
---

The ChatJS registry distributes editable source code using shadcn. A tool includes server logic, dependencies, and a declarative registration descriptor. Tools can include their own client renderer. Built-in search and code-execution items include renderers for their own output. Installed tools become part of your app's typed tool system. All installed and custom tools use native EVE definitions. Installed registry items use a `contractVersion: 1` descriptor. Custom tools are registered directly in `integrations/tools/execution.ts` without a descriptor.

```bash
npx chat-js@alpha add word-count
```

shadcn resolves the item and its dependencies, installs packages, and writes the source files. ChatJS then regenerates separate server and client registrations. Existing source follows shadcn's overwrite prompts. Pass `--overwrite` to replace it.

## Installed files

| File | Ownership |
| --- | --- |
| `chatjs/tools/<id>/tool.ts` | Editable server implementation |
| `chatjs/tools/<id>/renderer.tsx` | Editable client renderer |
| `chatjs/tools/<id>/chatjs.json` | Installed registration and environment descriptor |
| `chatjs/generated/tools.ts`, `ui.ts` | Generated registrations |
| `integrations/tools/execution.ts`, `integrations/tools/ui.ts` | Your custom registrations |

Keep manual registrations in the app-owned integration modules. Sync rejects duplicate installed descriptor keys and edited generated indexes. App composition permits explicit replacements; its workflow guard rejects dynamic tools that shadow native workflow names. Add app-owned tool names to the client-safe `integrations/tools/catalog.ts` when they should appear in tool selection. Sync also refuses to remove a previously registered tool just because its descriptor disappeared. Restore the descriptor before syncing.

Registry items specify explicit file targets. This integration uses `chatjs/tools`. The former `paths.tools` configuration and marker-based injection are removed. Built-in product tools remain in `tools/platform`.

## External registries

Configure standard namespaces in `components.json`:

```json
{
  "registries": {
    "@chatjs": "https://unpkg.com/@chat-js/registry@1/dist/r/{name}.json",
    "@acme": "https://example.com/r/{name}.json"
  }
}
```

```bash
npx chat-js@alpha add @acme/my-tool
```

You can also pass a complete registry item URL or local JSON path. Registry requests require HTTPS, with HTTP allowed for local loopback development. `--registry` has been replaced by standard namespace configuration.

## Direct shadcn installation

```bash
npx shadcn@4.21.0 add @chatjs/word-count
npx chat-js@alpha sync
```

shadcn installs source. `sync` reads installed descriptors and generates ChatJS registrations without evaluating third-party source. `chat-js add` performs both steps. If registration fails after installation, fix the reported issue and run `sync` again. Package installation is not transactional.

Tool environment requirements live in `chatjs.json`, generated from typed item metadata. `check-env` reads those descriptors without importing server tools.
