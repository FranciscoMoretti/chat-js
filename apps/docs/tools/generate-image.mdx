## Select during creation

```bash
npx chat-js@beta create my-app --yes --image-generation-tool generate-image
```

Interactive creation offers the built-in gateway implementation or an external registry item when you enable image generation. The installer checks that the [gateway](/gateways/overview#choose-a-gateway) declares image support and provides a default image model. Vercel, OpenAI, and OpenAI Compatible meet that requirement. Configure [durable storage](/storage) and verify that your endpoint serves the chosen image model.

## Installation

In an existing ChatJS app with registry-based image tools:

```bash
npx chat-js@beta add generate-image
```

Set `ai.tools.image.default` in `chat.config.ts`. Installation makes the tool available. There is no separate `enabled` flag.

You receive `chatjs/tools/generate-image/tool.ts`, `renderer.tsx`, and `chatjs.json`. Sync generates the registration and credential configuration. Fresh apps without image generation receive neither this implementation nor its renderer. Shared image viewing and storage helpers remain available to other app features.

## Behavior

On success, the tool receipt’s `output` contains `fileId`, `imageUrl`, and `prompt`. The ID identifies the stored file, and the URL opens it in ChatJS. It supports image creation and editing using attachments or the previous generated image. It uploads results through the configured Files SDK storage. The receipt uses gateway pricing and the image count or token usage, depending on the generation path. When pricing or required usage is unavailable, the cost is unknown.

### Model selection

If the selected chat model supports image output, the tool uses it. Otherwise, it uses `ai.tools.image.default`. The gateway supplies either a dedicated image model or a language model that supports image output.

```ts title="chat.config.ts"
import { defineConfig } from "@/lib/config-schema";

export default defineConfig({
  ai: {
    gateway: "vercel",
    tools: {
      image: { default: "google/gemini-3-pro-image" },
    },
  },
});
```

### Editing images

Ask for an image, then request a change such as "Add a lake in the foreground." The tool can combine inline image attachments from the latest user message with the most recent managed image returned by `generateImage` on the current branch.

While generation is running, the renderer shows a loading state with the prompt. On completion, it displays the generated image and copy controls.

## External implementations

```bash
npx chat-js@beta create my-app --yes \
  --image-generation-tool https://example.com/r/image-tool.json
```

Declare `slot: "generateImage"` in your registry metadata and installed descriptor. Export a native EVE tool with your own input/output schemas. A renderer is optional. External tools do not need a gateway image default. Declare provider credentials in `envRequirements` for the CLI checklist and app validation. Only one item can occupy this selection.

The installed implementation reads the native session model selection and imports ChatJS helpers for image context, model pricing, and authorized file upload. To participate in follow-up edits, the `generateImage` result must expose an `imageUrl` pointing to a managed ChatJS file. See [Authoring Tools](/tools/authoring).
