## Configuration

Set model defaults in `chat.config.ts`. This example assumes the Vercel gateway is installed:

```ts title="chat.config.ts"
import { defineConfig } from "@/lib/config-schema";

export default defineConfig({
  ai: {
    gateway: "vercel",
    providerOrder: ["openai", "google", "anthropic", "xai"],
    disabledModels: ["morph/morph-v3-large"],
    curatedDefaults: ["openai/gpt-5-mini", "google/gemini-2.5-flash-lite"],
    workflows: {
      chat: "openai/gpt-5-mini",
      title: "openai/gpt-5-nano",
    },
  },
});
```

| Setting | Purpose |
| --- | --- |
| `ai.gateway` | Discriminator for the installed gateway |
| `ai.providerOrder` | Provider order in the picker; unlisted providers follow |
| `ai.disabledModels` | Models hidden from the application catalog |
| `ai.curatedDefaults` | Recommended models ordered first and preferred when choosing a fallback |
| `ai.workflows.chat` | Default conversation model |
| `ai.workflows.title` | Title-generation model default |
| `ai.workflows.pdf`, `ai.workflows.chatImageCompatible` | Model IDs available to custom workflows. In built-in chat, the selected model must accept the attachment type. |
| `ai.tools` | Options contributed by installed tools, plus follow-up suggestion settings |

Changing `ai.gateway` alone does not install another provider. Follow the [gateway setup instructions](/gateways/overview) and review your model IDs after switching providers.

## Model discovery

The picker and EVE discover models from the installed gateway at runtime. ChatJS caches a successful catalog for one hour. After you add a model at the provider, it can take up to a cache refresh for it to appear in ChatJS.

Apps scaffolded with CLI `1.0.0-alpha.8` also have a bundled catalog for discovery failures. The current source relies on gateway discovery alone.

Vercel AI Gateway exposes a public catalog. With credentials, ChatJS also checks team eligibility. For other gateways, configure the model endpoint and credentials described in the gateway guide. If the picker is empty, check the server log for a discovery error. Verify the endpoint and credentials, then reload the app. If discovery succeeded, check the model list and visibility settings below.

## Visibility and preferences

ChatJS enables the gateway's discovered text-chat models by default. It removes models listed in `ai.disabledModels` and orders recommended models first. When installed, [Model Preferences](/plugins/model-preferences) lets each user hide models from their picker. These preferences affect picker visibility.

To offer a specific set of models to signed-in users, edit `integrations/chat/models.ts`.

```ts title="integrations/chat/models.ts"
export const webModels = {
  model: "openai/gpt-5-mini",
  modelIds: ["openai/gpt-5-mini", "google/gemini-2.5-flash-lite"],
};
```

Omit `modelIds` or leave it empty to use the gateway catalog. A populated list contains the complete set of eligible web chat model IDs. Include your preferred model in that list. If the preferred model is unavailable, ChatJS picks an eligible model from the catalog.

[Guest Chat](/plugins/guest-chat) owns its fixed model and locked picker. Guests do not create multi-model comparisons.

## Reasoning and parallel responses

Core derives model capabilities from catalog metadata. Models with reasoning support receive standard and reasoning variants. See [Reasoning](/core/reasoning) for behavior and configuration.

[Parallel responses](/core/conversations#parallel-responses) create independent runs from one or more selected models. That is conversation behavior, separate from catalog configuration and the optional Model Preferences plugin.

## Tool and plugin model defaults

Installed tools contribute their own schemas and defaults under `ai.tools`. Model settings do not install a tool. Image generation, video generation, search, retrieval, code execution, and deep research do not have an `enabled` configuration field.

| Capability | Configuration guide |
| --- | --- |
| Image model selection and inline image output | [Image Generation](/tools/generate-image) |
| Video model selection | [Video Generation](/tools/generate-video) |
| Research with the parent agent’s model | [Deep Research](/tools/deep-research) |
| Create and publish files from the sandbox | [Documents & Files](/tools/canvas) |
| Suggestion generation model and runtime enablement | [Follow-up Suggestions](/plugins/followup-suggestions) |

See [Configuration reference](/reference/config) for the complete configuration shape and [Prompts](/customization/prompts) for instructions sent to models.
