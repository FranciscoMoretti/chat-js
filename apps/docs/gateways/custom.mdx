Install a custom gateway when creating your app. If your endpoint implements the OpenAI API, you can also use the built-in [OpenAI Compatible](/gateways/openai-compatible) gateway.

```sh
chat-js create my-chat --gateway https://example.com/r/my-gateway.json
chat-js create my-chat --gateway ./my-gateway.json
```

Remote registry items and their dependencies require HTTPS. HTTP is supported for loopback development servers only.

## Author a registry item

Start from a built-in item in the [gateway registry](https://github.com/FranciscoMoretti/chat-js/tree/main/packages/registry/src/gateways). The [authoring contract](https://github.com/FranciscoMoretti/chat-js/blob/main/packages/registry/src/gateways/README.md) describes the complete metadata and adapter interface.

Your root item must use `type: "registry:item"`. Declare its SDK in `dependencies`, and include an adapter exporting `Gateway` at `~/chatjs/providers/gateway.ts`. Supporting files belong under `~/chatjs/providers/gateway/` and can come from `registryDependencies`.

Set `meta.chatjs` with:

- `kind: "gateway"`, `contractVersion: 1`, and a unique literal `id`.
- `capabilities` describing image and video support.
- Complete `defaults` for model lists, core workflows and `roles`: `smart`, `balanced`, `fast`, plus optional `image` and `video`. Use model IDs served by your endpoint. Tools select their own defaults from these roles.
- `envRequirements`, an array of required groups. Each group's `options` contains alternative sets of variables.
- `optionalEnv` for additional variables the adapter reads.

For example, an endpoint that requires a base URL and accepts an optional API key can declare:

```json
{
  "envRequirements": [{ "options": [["MY_GATEWAY_BASE_URL"]] }],
  "optionalEnv": ["MY_GATEWAY_API_KEY"]
}
```

This is a metadata fragment, not a complete registry item. Read declared credentials through the adapter's injected environment, such as `this.env.MY_GATEWAY_API_KEY` when extending `GatewayRuntime` from `@/chatjs/core/gateway/runtime`.

## Generated app

The shared runtime and types live in `chatjs/core/gateway/`. The CLI installs the selected adapter and dependencies, then writes `chatjs/providers/gateway-defaults.ts` with the gateway ID, defaults, capabilities, and environment declarations. `lib/env.ts` forwards those declared variables to the adapter, and `scripts/check-env.ts` checks the requirements. You do not add gateway entries to a central application registry or environment schema.

The generated `chat.config.ts` selects your gateway. Add credentials to `.env.local`, then verify the app:

```sh
bun test:types
bun dev
```

Select a model served by your endpoint and send a chat message to verify provider authentication and streaming. Type checks validate the adapter interface and configuration, but cannot verify remote credentials or model availability.
