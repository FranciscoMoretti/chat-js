title: "LiteLLM Gateway"
description: "Connect ChatJS to a LiteLLM proxy, use its model aliases for chat and titles, and verify model discovery from a generated app."
---

The LiteLLM gateway routes chat requests through your proxy. The proxy owns the upstream provider credentials. ChatJS needs its API base URL, a model alias, and a proxy key if authentication is enabled.

## Setup

1. Configure a model on the proxy. In this example, the upstream OpenAI credential belongs in the proxy environment. ChatJS will use the alias `chat-main`. [LiteLLM proxy setup](https://docs.litellm.ai/docs/simple_proxy)

```yaml title="litellm_config.yaml"
model_list:
  - model_name: chat-main
    litellm_params:
      model: openai/gpt-4o-mini
      api_key: os.environ/OPENAI_API_KEY
```

2. Select LiteLLM during app creation, or switch the gateway in an existing app. Run the command that matches your starting point.

```bash
# New app
npx chat-js@beta create my-chat --gateway litellm

# Existing app, from its root
npx chat-js@beta add --gateway litellm --replace
```

3. Set the API base URL in the app’s `.env.local`. For a proxy serving chat completions at `/v1/chat/completions`, include `/v1`. If the proxy requires authentication, also set `LITELLM_API_KEY` to a valid proxy key.

```dotenv
LITELLM_BASE_URL=http://localhost:4000/v1
```

4. In the existing `ai.workflows` block of `chat.config.ts`, set `chat` and `title` to `"chat-main"`. Use your own proxy aliases for any other workflow overrides. If you restrict the web picker, include an available alias in its [model list](/customization/models#visibility-and-preferences).

## Verify discovery and chat

With the proxy running, start the app, open the model picker, select `chat-main`, and send a message. Discovery requests `/v1/models`. Chat requests append `/chat/completions` to the configured base URL. If discovery succeeds but chat returns 404, compare that resulting chat path with the proxy route.

## Image Generation

The stock LiteLLM gateway has no default image model in its registry metadata. The CLI therefore rejects the built-in `generate-image` tool with this gateway, even if the proxy exposes an image endpoint. To use that endpoint, install an [external image tool](/tools/generate-image#external-implementations) that calls it, or package a [custom gateway](/gateways/custom) with image capability and an image model in `defaults.roles.image`.
