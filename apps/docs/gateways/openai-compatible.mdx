title: "OpenAI Compatible Gateway"
description: "Connect ChatJS to an OpenAI-compatible endpoint such as Ollama or LM Studio and discover the models available from that server."
---

Use this gateway when your inference server exposes OpenAI-compatible model listing and chat completions under the same base URL.

## Compatible Providers

This gateway works with:

- [Ollama](https://ollama.com) — local models on your machine
- [LM Studio](https://lmstudio.ai) — local model management with a GUI
- [vLLM](https://github.com/vllm-project/vllm): high-throughput self-hosted inference
- Other endpoints that serve `/models` and `/chat/completions` under one base URL and accept the adapter’s bearer token when authentication is required

## Setup

1. Set the base URL and (optionally) an API key in `.env.local`:

```bash
OPENAI_COMPATIBLE_BASE_URL=http://localhost:11434/v1  # Ollama example
OPENAI_COMPATIBLE_API_KEY=                             # Optional, depends on provider
```

2. Install the gateway source (add `--replace` when another gateway is installed):

```bash
bunx chat-js@alpha add --gateway openai-compatible
```

In your existing `chat.config.ts`, merge the workflow values below into the `ai` block. Keep the other settings for your app.

```typescript title="chat.config.ts"
import { defineConfig } from "@/lib/config-schema";

export default defineConfig({
  ai: {
    gateway: "openai-compatible",
    workflows: {
      chat: "llama3.2",
      title: "llama3.2",
    },
  },
});
```

## Authentication

| Variable | Description |
| --- | --- |
| `OPENAI_COMPATIBLE_BASE_URL` | Required. The base URL of the API (e.g., `http://localhost:11434/v1`) |
| `OPENAI_COMPATIBLE_API_KEY` | Optional. API key if the provider requires authentication |

## Available Models

Set the base URL to the API prefix, such as `http://localhost:11434/v1`, without a trailing slash. ChatJS reads `/models` under that prefix and caches discovery for one hour. The adapter reports IDs as language models. Limit the [web picker](/customization/models#visibility-and-preferences) to IDs your server accepts for chat.

### Ollama

After [installing Ollama](https://ollama.com/download), pull models and they appear automatically:

```bash
ollama pull llama3.2
ollama pull codellama
```

### LM Studio

Download models through the LM Studio UI, then start the local server. Models appear at `http://localhost:1234/v1/models`.

```bash
OPENAI_COMPATIBLE_BASE_URL=http://localhost:1234/v1
```

## Image Generation

Image generation support depends on the provider. If the endpoint supports the OpenAI image generation API format, `createImageModel()` will work. Set `ai.tools.image.default` to an image model the endpoint serves. The built-in adapter reads model IDs without image-output tags, so it cannot discover an inline image-generation model from this catalog.
