---
title: Git Worktrees
description: "Run two ChatJS checkouts side by side with Git worktrees, install their dependencies, and find the app URLs assigned to each development environment."
---

Use a separate Git worktree when you need to run two versions of the ChatJS repository at once. Each checkout has its own dependencies and local environment files.

## Create and configure a checkout

From your repository root, create a branch and check it out in a sibling directory.

```bash
git worktree add -b feature-auth ../chatjs-feature-auth
cd ../chatjs-feature-auth
bun install
```

Configure the reference app's credentials in the worktree's root `.env.local`, as you would for a fresh checkout. Use an isolated database when testing schema changes. See [Neon branching](/cookbook/neon-branching) for the repository helpers.

## Give the checkout its own ports

Set `CHATJS_DEV_SLOT` in `.env.worktree.local` to a nonnegative integer that differs from your other active worktrees. For example, if your main checkout uses the default slot of zero, use this in the second checkout.

```dotenv title=".env.worktree.local"
CHATJS_DEV_SLOT=1
```

Run these commands from the worktree root. The first prints the assigned URLs for chat, the site, docs, and EVE. The second starts the reference app.

```bash
bun dev:info
bun dev
```

## Remove a finished checkout

Commit or save the changes you need and stop its development server. From a different checkout, inspect the worktrees, then remove the finished directory.

```bash
git worktree list
git worktree remove ../chatjs-feature-auth
```

The branch remains available after removing the checkout.
