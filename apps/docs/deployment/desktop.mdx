Install and configure the [Desktop plugin](../plugins/desktop) before packaging. The Electron companion loads your hosted ChatJS app. Set the deployed app URL and use matching app identity and protocol settings in both builds.

The [ChatJS release history](https://github.com/FranciscoMoretti/chat-js/releases) contains reference-app installers. The instructions below package your own application.

## Auto-Updates

The desktop integration uses `update-electron-app` with a public GitHub repository. Packaged builds check GitHub Releases for newer versions automatically.

## Customization

### App icon

Replace `electron/icon.png` with your own 512x512 PNG, then regenerate the platform-specific assets:

```bash
cd electron
bun run generate-icons
```

### App name, scheme, and production URL

Edit `chat.config.ts` in your project root:

```ts
const config = {
  appName: "My App",
  appPrefix: "myapp",
  appUrl: "https://my-app.vercel.app",
};
```

Before each build, the Electron prebuild step writes a `branding.json` file from those values and the plugin's `protocol.ts`. The native runtime imports this generated configuration instead of web-app modules. Rebuild after changing these settings.

Use `electron/forge.config.ts` for packaging-specific settings. Keep the app identity and URL in `chat.config.ts` so protocol registration, authentication callbacks, and packaged builds use the same values.

## Building for Distribution

Build desktop installers from the `electron/` directory:

```bash
cd electron
bun run make:mac
bun run make:win
bun run make:linux
```

Build outputs are written to `electron/out/`.

- **macOS**: `.dmg` and `.zip`
- **Windows**: `.exe` installer
- **Linux**: `.deb` and `.rpm`

To test the packaged app without an installer, use:

```bash
bun run package
```

## macOS Distribution Notes

For public macOS distribution outside the App Store, you will usually want:

- code signing
- notarization
- a stable bundle identifier and install path

The generated app includes the hardened runtime entitlements file, but notarization and signing still require your Apple Developer credentials and CI setup.

## Release automation

Configure publishing for your own repository and distribution targets. [Desktop Release Process](../reference/desktop-releases) documents the ChatJS maintainer workflow as a reference.
