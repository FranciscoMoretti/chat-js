---
title: Deploy to Vercel
description: "Deploy ChatJS and its integrated EVE worker to Vercel, configure preview and production credentials, and initialize the application database."
---

Deploy your generated app as one Next.js project. Vercel Preview and Production use managed Workflow for EVE execution and transcripts. You still need PostgreSQL for application data. Start with an app that can send a message locally. [Quickstart](/quickstart)

## 1. Connect the app and its services

Import the app's Git repository into Vercel. If the app lives in a monorepo, select the app directory as the project's root. Keep **Automatically expose System Environment Variables** enabled so ChatJS can select the workflow backend.

| Service | What to configure |
| --- | --- |
| PostgreSQL | Set `DATABASE_URL` for each environment. Use separate databases for preview and production. Set `DATABASE_MIGRATION_URL` if migrations need a separate connection. |
| AI gateway | Configure the gateway installed in your app. The default Vercel AI Gateway can use deployment OIDC. Other adapters use their own credentials or endpoint. [Gateways](/gateways/overview) |
| File storage | Configure your installed adapter if you selected uploads or generated media. For Vercel Blob, connect a private store and supply its read/write token or supported OIDC settings. [File storage](/storage) |
| Sandbox | Configure the environment selected in `agent/sandbox.ts`. Vercel Sandbox can authenticate with deployment OIDC. [Sandboxes](/deployment/sandboxes) |

## 2. Set credentials and origins

Set `AUTH_SECRET` and `EVE_GATEWAY_SECRET` to independently generated secrets. Run `openssl rand -base64 32` once for each. Supply credentials for every enabled OAuth provider and any installed capabilities in the generated `.env.example`. Make them available during build and runtime. [Environment variables](/reference/env-vars)

For production, set `APP_URL` to your public origin and register that origin's OAuth callback URLs. For example, GitHub uses `https://yourdomain.com/api/auth/callback/github`. Without an explicit `APP_URL`, production auth falls back to `appUrl` in `chat.config.ts`.

### Preview origins and OAuth

Register your preview branch's stable hostname with each enabled OAuth provider. In Preview, ChatJS uses `VERCEL_BRANCH_URL` and then `VERCEL_URL` when `APP_URL` is unset. An inherited production `APP_URL` would send preview sign-ins to the wrong origin.

Leave `EVE_INTERNAL_ORIGIN` unset for the integrated worker. Its default on Vercel uses the exact deployment URL, even when OAuth uses the stable branch alias.

### Protected previews

If Deployment Protection blocks internal calls, enable **Protection Bypass for Automation** and make `VERCEL_AUTOMATION_BYPASS_SECRET` available to the deployment. Redeploy after changing environment settings. ChatJS forwards the secret only to an EVE origin matching the deployment or branch hostname. The gateway also checks the EVE credential and owner identity.

## 3. Initialize the database and deploy

Production builds apply tracked application migrations. Preview builds skip them. Apply reviewed migrations to the **preview database** before testing that deployment. Vercel provisions the managed workflow backend, so omit `WORKFLOW_POSTGRES_URL`. See [hosted workflow setup](/reference/database#hosted-workflow-database).

In a generated app, run the [workflow backend check](/reference/database#check-the-workflow-backend-before-deployment) explicitly after migrations with the target deployment’s environment. It records the backend on first use and rejects a later mismatch. Use an isolated database for a new preview. Moving existing sessions between backends requires a separate migration. Hosted conversation erasure remains unavailable.

After deploying, sign in, send a message, and reload the chat. If you installed uploads, also attach a file and reopen it from the saved conversation.

## Cron jobs

The schedule in `vercel.json` calls `/api/cron/cleanup` daily at 02:00 UTC. Set `CRON_SECRET` in Production so the scheduler can authenticate. The route returns 401 for a missing or incorrect bearer token and 503 when cleanup is incomplete. Check the deployment logs for that route if scheduled cleanup fails.

To extend cleanup, add to the app's task list in `integrations/cleanup.ts` or contribute a task from a plugin. [Plugin cleanup tasks](/reference/plugin-api)

## Production controls

Review the project domain, OAuth callbacks, gateway spending limits, and storage configuration before opening sign-ups. Apply rate limits appropriate to your traffic on the authenticated EVE endpoints. [Vercel Firewall](https://vercel.com/docs/vercel-firewall)
