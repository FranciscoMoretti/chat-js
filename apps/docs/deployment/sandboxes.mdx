title: Sandboxes
description: Configure EVE's native sandbox environment
---

The agent's `agent/sandbox.ts` selects a native EVE sandbox environment. EVE owns its files, processes, resume and cleanup. ChatJS assembles the selected file and keeps authorization on application-owned uploads and published files.

## Select a provider

| Builder choice | Behavior |
| --- | --- |
| Automatic | EVE selects Vercel on Vercel, Docker when available, or a simulated shell in development. |
| Vercel Sandbox | Hosted sandbox with native Python and Node processes. |
| Docker | Containers on a reachable Docker host, with native Python and Node processes. |
| just-bash | Simulated shell and filesystem; cannot run native Python or Node processes. |

New agents enable native default tools, including `bash`. Selecting a sandbox chooses where those tools work; it does not install a second execution tool.

```bash
bunx chat-js@alpha create my-app --yes --sandbox-provider docker
```

The generated file uses EVE directly:

```ts title="agent/sandbox.ts"
import { DockerSandbox, defineSandbox } from "eve/sandbox";

export const environment = DockerSandbox.environment();
export default defineSandbox(async () => await environment.open());
```

For an existing app:

```bash
bunx chat-js@alpha add --sandbox-provider vercel --replace
```

The CLI accepts `default`, `vercel`, `docker`, `just-bash`, or a sandbox registry address. Review customized source before using `--overwrite`. Native EVE files remain editable for image preparation and provider-specific options.

## Credentials

Docker needs a reachable Docker daemon. Vercel Sandbox uses Vercel OIDC when available, or these credentials outside Vercel hosting:

```bash
VERCEL_TEAM_ID=team_xxx
VERCEL_PROJECT_ID=prj_xxx
VERCEL_TOKEN=your_token_here
```

The generated `.env.example` and `check-env` command describe the selected environment requirements. Secrets belong in environment variables.

## Files and documents

Sandbox paths are agent workspace files. To make a finished file available after the sandbox ends, install `publish-file` and persistent application storage. The tool creates an immutable byte snapshot with ChatJS access controls. Optional viewer plugins can open it in chat. See [Code execution and publication](../tools/code-execution).

## Lifecycle and accounting

EVE manages sandbox sessions, cancellation and background processes. ChatJS does not restore a second sandbox filesystem or maintain a custom execution provider. Native execution does not add a fixed ChatJS tool charge. Infrastructure provider billing remains separate from model usage.
