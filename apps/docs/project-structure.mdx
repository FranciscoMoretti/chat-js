Paths on this page start at the root of your generated app. In the ChatJS repository, the reference app lives in `apps/chat/`.

## Where to make a change

| If you want to… | Start here |
| --- | --- |
| Change branding, OAuth providers, or model defaults | `chat.config.ts`. See [Configuration](/core/configuration). |
| Change the agent's model policy or tool approvals | `agent/agent.ts`. EVE loads the channels, instructions, hooks, and tools under `agent/`. |
| Change instructions for signed-in chats | `lib/ai/prompts.ts`, loaded by `agent/instructions/chat.ts`. See [Prompts](/customization/prompts). |
| Adjust the transcript or composer layout | `components/chat/chat-conversation-screen.tsx`. See [Chat layout](/cookbook/chat-layout). |
| Change sign-in or session handling | `lib/auth.ts` on the server and `lib/auth-client.ts` in the browser. See [Authentication](/customization/authentication). |
| Change an installed plugin or tool | `chatjs/plugins/<id>/` or `chatjs/tools/<id>/`. Put app-specific composition in `integrations/`. See [Source ownership](/core/source-ownership). |

## Routes and data

The Next.js App Router keeps sign-in pages under `app/(auth)/` and the chat interface under `app/(chat)/`. Plugins can add routes to either the app or the API. See [URL routing](/reference/routing) for the public paths and their identifiers.

| Directory | Responsibility |
| --- | --- |
| `app/api/eve/[...path]/` | Authenticate browser requests and forward authorized operations to EVE |
| `app/api/agent-conversations/` | Manage application-owned conversation metadata |
| `app/api/trpc/[trpc]/`, `trpc/` | Serve the composed tRPC routers |
| `lib/db/` | Define the Drizzle schema, migrations, and queries for application data |
| `lib/eve/` | Connect ChatJS ownership, branches, and lifecycle operations to native EVE sessions |
| `lib/ai/` | Resolve the installed gateway and discover its models |

EVE stores the transcript and execution state. ChatJS stores the identity and ownership records that let a signed-in user find and reopen a chat. See [Architecture](/core/architecture) for the request flow.

## Installed and generated files

| Path | What to do with it |
| --- | --- |
| `chatjs/core/`, `chatjs/providers/` | Inspect the shared contracts and your selected gateway and storage adapters. |
| `chatjs/plugins/`, `chatjs/tools/` | Edit installed implementations. Some items also install native route or agent entry files. |
| `integrations/` | Compose or wrap installed behavior in your app. |
| `chatjs/generated/` | Change the source descriptors and run [sync](/cli/sync) to regenerate registrations. |
| `chatjs/installed-source.json` | Commit the receipt so the CLI can identify locally edited files on subsequent installs. |

Use [status](/cli/status) to see which plugin owns a file. If you contribute to ChatJS itself, edit installable source in `packages/registry/src/` and its manifest. The [registry mirror](/registry/mirror) copies those files into the reference app.
