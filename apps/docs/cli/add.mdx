---
title: add
description: Install registry tools, plugins and providers
---

```bash
npx @chat-js/cli@latest add [items...] [options]
```

Accepts built-in names, standard `@namespace/item` addresses, complete item URLs, and local registry JSON paths. Run inside a ChatJS app with `chat.config.ts`.

| Flag | Default | Description |
| --- | --- | --- |
| `-y, --yes` | `false` | Skip ChatJS confirmation |
| `-o, --overwrite` | `false` | Authorize overwriting modified or untracked source |
| `--dry-run` | `false` | Resolve and report declared integrations and native entry paths without installing or writing app files |
| `--files-only` | `false` | Export source and connection metadata to a temporary review directory |
| `--replace` | `false` | Explicitly authorize exclusive provider replacement |
| `--sandbox-provider <item>` | None | Select optional sandbox infrastructure: Vercel, Daytona or a registry address |
| `--gateway <item>` | Not applicable | Select an AI gateway |
| `--storage-provider <item>` | Not applicable | Select file storage |
| `--storage-config <json>` | Not applicable | Non-secret storage adapter options |
| `-c, --cwd <cwd>` | Current directory | Destination app |

```bash
npx @chat-js/cli@latest add word-count get-weather --yes
npx @chat-js/cli@latest add @acme/my-tool
npx @chat-js/cli@latest add ./my-tool.json --cwd apps/chat
```

Configure namespaces in `components.json`. The former `--registry` flag is removed. shadcn installs source and packages using the project's detected package manager, then ChatJS syncs local tool descriptors into typed registrations.

Install optional implementations together or independently:

```bash
npx @chat-js/cli@latest add attachment-uploads mcp vercel-analytics vercel-speed-insights langfuse --sandbox-provider vercel --storage-provider vercel-blob --yes
```

Uploads require durable storage and a sandbox with persistent-file support. Existing compatible providers satisfy these requirements. The CLI rejects replacing that sandbox with an incompatible provider while uploads remain installed.

UI plugins export typed contributions with `definePlugin`. The CLI updates generated installed-plugin lists and preserves your component edits and app layout JSX. Move slot components or wrap contributed components to customize placement and behavior.

After direct shadcn source installation, regenerate registrations with `sync`:

```bash
npx @chat-js/cli@latest sync --cwd apps/chat
```

The command prints the selected integrations' credential requirements. Copy them into `.env.local` and run `bun run setup`. Langfuse needs both `LANGFUSE_PUBLIC_KEY` and `LANGFUSE_SECRET_KEY`, while MCP needs `MCP_ENCRYPTION_KEY`.

Exclusive alternatives require explicit replacement:

```bash
npx @chat-js/cli@latest add firecrawl-search --replace --yes
npx @chat-js/cli@latest add --storage-provider s3 --storage-config '{"bucket":"uploads","region":"eu-west-1"}' --replace --yes
```

`--yes` skips confirmation. It does not authorize replacement or overwriting edited files. ChatJS records installed-source hashes in `chatjs/installed-source.json`. Changed or untracked source is protected until you review it and explicitly pass `--overwrite`. This includes source installed with native shadcn, which has no ChatJS baseline. Keep the baseline in version control. Unrelated tools and plugins remain installed, and previous tool-provider source is retired only after registration succeeds.

Gateway replacement updates the gateway discriminator and provider configuration while preserving your model IDs and runtime settings. Review those model IDs for the new gateway and run `bun run setup` and `bun run fetch:models`.

If source installation or registration fails, the command exits unsuccessfully. Previous tool-provider source is restored, but newly installed source or packages may remain. Review the partial installation and retry the same `add` command with `--overwrite`, or integrate the source manually and run `sync`. This CLI supports creation, add, explicit exclusive replacement, and plugin removal with `chat-js remove`. It does not automatically upgrade older app templates.

## Inspect activation first

Run `chat-js add <item> --dry-run` to resolve the proposed installation and inspect its wiring before mutation. This can read a registry over the network. It does not install packages, run source, write app files, or record source hashes.

The output separates app-owned integration modules, known Next.js/EVE entry paths, and ordinary framework source. It classifies explicit `~/` targets. Other shadcn destinations are reported as unresolved rather than guessed. Native path matches are an inventory, not proof that an export or framework setting activates them. Registering a database schema does not apply a migration.

Use `--files-only` when you want source to review and connect manually. It exports files and metadata into a temporary directory without installing or activating them in your app. You cannot combine it with `--dry-run`.
